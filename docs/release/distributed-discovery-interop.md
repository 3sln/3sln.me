# Distributed discovery interoperability review

**Historical research — feature withdrawn.** The user explicitly deferred distributed/Web3 discovery on 2026-10-12 after reviewing the resolver and gateway availability findings. The proposed implementation and its dependency were removed from the SDK. The observations below explain that decision; they do not describe a supported release feature.

Independent agent review, 2026-10-12. Scope: SDK resolver profiles, DNSLink-to-manifest transport, issuer delegation, and public resolver/browser observations. ## Primary-source baseline

- Cloudflare's [distributed web announcement](https://blog.cloudflare.com/cloudflare-distributed-web-resolver/) describes ENS content discovery through IPFS. Its [API deprecation record](https://developers.cloudflare.com/fundamentals/api/reference/deprecations/) explicitly retires the `resolver.cloudflare-eth.com` DoH experiment on July 1, 2025. Ordinary Cloudflare DNS is not an ENS substitute.
- [Kubo v0.33's changelog](https://github.com/ipfs/kubo/blob/master/docs/changelogs/v0.33.md#new-doh-resolvers-for-non-icann-dnslinks) selects `dns.eth.limo` for `.eth` and `resolver.unstoppable.io` for `.crypto`. This establishes endpoint provenance; it does not establish current availability, JSON compatibility, CORS, or Bindle support.
- [eth.limo's current DoH documentation](https://github.com/ethlimo/documentation/blob/master/introduction/what-is-eth.limo/gateway-basics/dns-over-https.md) describes GET JSON, `type=TXT`, string `Status`, lowercase `ttl`, and DNSLink derived from contenthash. Arbitrary ENS text records are outside that documented interface.
- [IPFS web-addressing documentation](https://docs.ipfs.tech/how-to/address-ipfs-on-web/#subdomain-gateway) supports the implementation's CIDv0-to-base32-CIDv1 conversion and isolated CID subdomain form. Labels exceeding 63 characters cannot use this form; failing closed is appropriate for the defined profile.

## Live observations

Public names below identify read-only observations of existing third-party data, not project deployment examples or names controlled by this project. No paid service, provisioning, publication, login, or active security probing occurred.

At approximately 22:13–22:15 UTC on 2026-10-12, a GET to `https://dns.eth.limo/dns-query?name=_dnslink.vitalik.eth&type=TXT` with `Accept: application/dns-json` and `Origin: https://app.example` returned HTTP 200, `Access-Control-Allow-Origin: *`, and `Content-Type: application/x-javascript`. Its JSON contained `Status: "0"`, `TC: false`, the exact requested question/answer name and TXT type 16, lowercase `ttl: 300`, and `dnslink=/ipfs/bafybeiesmy6rsaglneqxbzkbdj5degzp2izydfadhl2vu3oyrp7k52fypu`.

Actual headless Chrome, on an intercepted empty page at reserved origin `https://app.example`, fetched that live resolver URL with omitted credentials, redirect refusal, no referrer, and a ten-second timeout. Browser JavaScript successfully read the same status, MIME type, and JSON. This verifies browser CORS for this public ENS query, independently of Node fixtures. It does not verify a Bindle manifest or authentication on that name.

A HEAD to the corresponding `https://bafybeiesmy6rsaglneqxbzkbdj5degzp2izydfadhl2vu3oyrp7k52fypu.ipfs.dweb.link/.well-known/bindle/manifest.json` returned HTTP 429, `Retry-After: 900`, `Access-Control-Allow-Origin: *`, `Sunset: Mon, 21 Sep 2026 00:00:00 GMT`, and a sunset link to [the gateway retirement notice](https://gatewaychanges.ipfs.io/). That notice describes permanent retirement on September 21 and directs applications to move gateway traffic. This is gateway retirement evidence; it cannot establish whether that public CID contains a Bindle manifest.

A bounded HEAD for the same CID and path at `https://<CID>.ipfs.w3s.link` at 22:15:51 UTC returned HTTP 301 to the corresponding retired `ipfs.dweb.link` URL. Redirect refusal correctly rejects it. The previously suggested [Storacha retrieval documentation](https://docs.storacha.network/how-to/retrieve/) currently redirects to a different product's landing page. Neither observation supports selecting that gateway as a maintained universal default; no replacement operator was nominated without sufficient evidence.

GETs to `https://resolver.unstoppable.io/dns-query?name=_dnslink.brad.crypto&type=TXT` timed out before any HTTP response: one after twenty seconds, one explicitly over IPv4 after fifteen seconds. This observation is specific to the review machine/network and does not prove global unavailability. JSON response shape and browser CORS for this `.crypto` endpoint remain unverified.

## Findings and required disposition

1. **ENS MIME mismatch — fixed during review.** The initial generic DNS JSON MIME check rejected the live eth.limo response. The SDK owner added explicit trusted-profile `acceptJavaScriptJSON: true` compatibility for `application/x-javascript`; response bounds and JSON parsing remain in force. No script is evaluated. Independent rerun of `node --test packages/sdk/test/identity.test.mjs` passed 22/22, including acceptance only with the opt-in and rejection without it. This exception must remain a trusted configuration choice, never a response-selected parser mode.
2. **Retired gateway default — required reconciliation.** The initial `https://ipfs.dweb.link` default no longer provides a working retrieval dependency. Remove that implicit dependency. Require an application-configured reviewed isolated gateway, or replace it only after separately verifying the new operator's present policy, subdomain routing, JSON response behavior, CORS and availability. A missing required gateway must produce a clear discovery error and must never materialize an email account. Do not describe this profile as an operational out-of-box end-to-end default while its gateway is retired or unconfigured.
3. **`.crypto` evidence gap.** Keep configurable protocol support distinct from verified external operation. Kubo's historical selection is not sufficient evidence of current JSON/CORS interoperability. Do not silently replace this namespace with ordinary DNS, and preserve explicit failure on timeout.
4. **Private-host wording exceeds hostname checks.** URL validation rejects literal IPs and selected localhost/local spellings. It does not establish that every hostname resolves to a public address or prevent DNS rebinding. The canonical-issuer path initially used `parseIdentity`, which permits `provider.local`. Documentation should describe exact validation and trusted configuration, not promise general private-network isolation. Browser-local discovery does not add a server-side URL-fetch proxy.

## Architecture assessment

The trust boundary is coherent for an explicitly trusted resolver/gateway profile. A DNSLink manifest may delegate to a canonical HTTPS issuer; that issuer then owns all authorization, request, token, RPC and JWKS endpoints. The original entered alias remains separate, while the authorization handle uses the unchanged username and canonical issuer host. A provider need not treat an unverified foreign name as its native account identity. Ordinary direct HTTPS discovery and TXT-origin delegation retain their own retrieval-origin/issuer restrictions.

The implementation trusts resolver answers and gateway bytes. CID syntax/conversion and isolated origins do not locally verify Ethereum state or IPFS block hashes. Because the gateway may influence the issuer by changing JSON, it is an authentication trust dependency, not merely an availability service. The current spec discloses that limitation appropriately. Application UI should expose the resolved issuer before navigating; successful name resolution alone does not establish permanent ownership or a stable UUID account binding.

Question/answer binding, a single matching TXT answer, record/body size limits, bounded requests, refusal of redirects, restricted DNSLink paths, no IPNS interpretation, and failure without email fallback for a selected distributed profile are sensible initial constraints. Multiple TXT encodings outside the supported form, longer CID labels, other multibase forms, Unicode ENS normalization beyond URL hostname processing, unsupported contenthash schemes, and provider-specific naming behavior must not be implied to work without dedicated profiles/tests.

The repository's browser federation test intercepts resolver and gateway responses, then exercises actual local Worker OAuth, consent, callback and scoped RPC. That proves the composed local implementation with fixtures. Combined with the live ENS first-hop observation above, it still does not prove end-to-end authentication through an independently operated distributed name, public manifest and external Bindle provider. Full-suite results and final fixes belong in DEVLOG.md; release remains gated.
